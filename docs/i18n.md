# Internationalization

## Language behavior

Kestrel uses English (`en`) on first use, including on a non-English host. A saved, supported language takes precedence. An absent, invalid, or unsupported selection resolves to English. Language selection does not require an account and is not synchronized between devices.

The supported languages are Traditional Chinese (`zh-TW`), English (`en`), Japanese (`ja`), Korean (`ko`), Hindi (`hi`), Spanish (`es`), French (`fr`), Portuguese (`pt`), Indonesian (`id`), German (`de`), Vietnamese (`vi`), Turkish (`tr`), Filipino (`fil`), Thai (`th`), Italian (`it`), Polish (`pl`), Malay (`ms`), and Dutch (`nl`).

Language selectors show native and English names in a fixed order. Flags do not identify languages. Android language selection belongs in Settings. Web language selection belongs in Account settings and is also available before sign-in and on public share pages.

Normalize regional variants of language-only catalog tags to the base language. Examples: `en-US` → `en`, `pt-BR` → `pt`, and legacy Indonesian `in` → `id`. Explicit Traditional Chinese tags (`zh-TW`, `zh-Hant`, `zh-Hant-*`) resolve to `zh-TW`. Bare `zh` and Simplified Chinese do not resolve to Traditional Chinese. Malformed tags resolve to English.

### Exclusions

Do not translate user-provided place/route names, descriptions, tags, device names, server addresses, or configured OIDC provider names. Do not rewrite saved names when the language changes. Localized default names apply only to newly created content.

Keep Kestrel, MapLibre, Android, Google Play services, protocol identifiers, enum values, API paths, asset statements, URLs, tokens, recovery codes, and diagnostic logs unchanged. Legally required map attribution must remain intact. Basemap labels, scanner UI, OS permission dialogs, and external identity-provider pages remain controlled by their providers.

Coordinate input and copy output use decimal points and the existing parseable syntax. JSON numbers, API timestamps, route calculations, IDs, and data storage do not depend on the UI language. Localized display must not change units or time-zone behavior.

## Catalog and message rules

Android uses complete default English resources under `app/src/main/res/values/`. Translated resource directories follow the table in the implementation plan. Web uses namespaced ICU messages in `web/messages/<locale>.json`; `en.json` is its source catalog. The two platforms have separate catalogs because their UI and plural APIs differ.

Use canonical `id` in language choices, metadata, Web catalogs, and stored selections. Android resources must use the legacy `values-in` directory. `values-b+id` falls back to English on API 32. Resource tests must check translated values, not only nonempty strings, to detect this failure.

Use stable semantic keys, not English sentences as keys. Translate complete messages. Do not concatenate translated sentence fragments. Add translator context for ambiguous actions or technical concepts. Do not render translator-supplied HTML. Interpolated user content must remain escaped.

Preserve the names and types of arguments. Use numbered Android format arguments where a message has multiple arguments, such as `%1$s` and `%2$d`. Use Android `plurals` and ICU `plural` for counts. Include the plural categories required by the target platform and language; do not assume English singular/plural rules apply to Polish or Filipino.

A missing message uses English at runtime and must not show a key or crash. This is a safety fallback, not a translation-completeness exemption. Release checks must reject missing keys, malformed resources, invalid ICU, empty messages, and incorrect argument types.

### Glossary and style

| Concept | Meaning to preserve |
| --- | --- |
| Mock location | An Android test location, not a claim to bypass detection |
| Preview | A proposed target; does not start or replace a mock |
| Play route | Start mock movement along a route |
| Pause / Resume / Stop | Distinct playback actions; preserve their effects |
| Once / Loop / Ping-pong | Playback modes; never translate persisted enum identifiers |
| Place / Route / Favorite / Library | Preserve each surface's existing content ownership |
| Sync conflict | A local/cloud version conflict requiring an explicit choice |
| Remote control | Web-issued commands to an explicitly enabled Android device |
| Sign out / Revoke session | Different session actions; do not merge them |

Use concise, direct UI language. Do not shorten safety or destructive-action warnings to fit a fixed width. Traditional Chinese must use Traditional script. Portuguese uses one generic `pt` catalog: use consistent, broadly understood terminology without a separate regional dialect catalog. English and Spanish also use one source/translation variant each. Review terminology consistently across Android and Web while allowing platform-specific wording.

## Error contract audit

`backend/src/http/handlers.ts` preserves explicit exception response objects, including codes, but many responses contain only an English message and HTTP status. Code-bearing synchronization errors include `SYNC_CURSOR_EXPIRED` and `CLIENT_MUTATION_ID_REUSED`. Client presentation must map stable codes first and then status plus operation context. Do not infer behavior or translation by matching English response prose.

Android `CloudApiException` already retains the optional `code`. Web `ApiError` must retain it without exposing raw response bodies in the UI. Unknown errors need a localized generic message; status context must remain safe. Preserve actionable authentication, conflict, expired-link, rate-limit, and retry behavior. Never log bodies, credentials, tokens, precise locations, or full query strings for translation diagnostics.

No backend schema, error-protocol, or database migration is part of this change.

## Review and acceptance evidence

Translation review is a delivery dependency. Generated translations are drafts until an independent, qualified language reviewer has reviewed terminology, script, argument use, plural branches, and representative UI. An automated catalog pass proves structure, not linguistic quality. No human language reviewer is assigned in this checkout; do not mark the translation-review plan tasks complete without recorded evidence.

Record each locale's reviewer, reviewed revision, issues, and resolution in the implementation plan or linked review notes. A machine-generated catalog must not be described as human-reviewed. Unavailable reviewers and device checks remain open acceptance items.

Browser verification uses Chrome DevTools, not Playwright, at 1440×900 in light mode. Check each requested language on login, Map, Library, Account, and public shares. Check glyph shaping, long labels, keyboard and accessible names, draft retention, document language, metadata, and hydration. Keep all screenshots outside Git.

Android verification covers API 29–32 and API 33+, initial English on a non-English host, persisted selection, Android Settings integration, activity recreation, callbacks, active/paused routes, notification channel labels, and font scaling. Obtain approval before commands that install, replace, clear, or otherwise change a connected user's device state. Do not reset application data as a localization test or recovery step.

Mutating runtime tests require an approved disposable Android emulator. Their rule checks emulator hardware and the opt-in argument **before** launching an Activity.

| Test class | Required instrumentation argument | State that can change |
| --- | --- | --- |
| `LocaleLifecycleTest` | `localeLifecycle=true` | Language, preview, and camera state |
| `LocalePlaybackTest` | `localePlayback=true` | Language, this test's mock route, and camera preferences |
| `LocaleLayoutTest` | `localeLayouts=true` | Language and camera preferences; captures app UI |

Pin the exact adb serial and verify its AVD name before each mutation batch. Playback tests require idle runtime and no saved mock, stop only their own route, and preserve failures from cleanup. Layout captures are written to the target app's `cache/i18n-layout-<fontScale>/`; copy them outside the repository for review. Do not weaken viewport, 48dp touch-target, or keyboard-focus assertions to make translations pass.

## Current validation limits

The translated catalogs are machine-generated drafts. Structural checks and independent model review do not replace qualified language review. Keep the delivery pull request in draft until the implementation plan's remaining acceptance items have evidence.

Web browser checks use an isolated, read-only API fixture. These checks cover localized rendering and language-switch behavior, not a production backend, real identity provider, or physical remote-control device. Android resource tests alone do not prove playback, migration, notification refresh, or layout behavior. The implementation plan records separate runtime checks on API 32/33, a simulated AppCompat-file migration, and all-language native captures at font scales 1.0/1.5; this is not a physical-device OS upgrade or a production integration test.

## Contributor workflow

1. Add or change the English resource/message and all call sites.
2. Update all 17 translated catalogs, including plural branches and argument types.
3. Obtain language review and record evidence.
4. Run catalog validation and platform tests.
5. Verify affected UI and lifecycle behavior. Keep unavailable checks open.

Use Java 26 for Android and Node.js 22 for Web. Run `cd web && npm ci` on first use and after the lockfile changes.

Required checks:

```bash
just i18n-check
just android-check
just android-lint
just android-test
just android-ui
just android-build
just android-resource-lint
just web-check
cd web && npm test
# Run the following from the repository root.
just web-typecheck
just web-build
```

Run checks as separate observable steps. Do not commit generated caches, screenshots, or binary reference images. A failed or unavailable check is not a pass.
